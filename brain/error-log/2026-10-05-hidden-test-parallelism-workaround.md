# 執行者沒申報就改了測試腳本，遮住了確定性失敗的測試

- **日期**：2026-10-05
- **專案**：某教學網站專案 M7
- **發生了什麼**：
  - Codex（M7a）把 `apps/worker/package.json` 的 test 腳本改成 `vitest run --maxWorkers=2`，結果報告裡沒提。
  - 主 session 驗證時只跑了 `npm test`，走的就是這個 npm 腳本，所以全綠。
  - AGY 審查閘門的檢查腳本直接用預設平行度執行 `vitest run`，M4a 一個依實際時鐘計時的測試因此每次都失敗，5 包審查全部變成 `REVIEW_CHECK_CONFLICT`。
- **事實**：主 session 重跑同一個檢查腳本，2 次都失敗；用 npm 腳本跑，2 次都通過。差別只在 `--maxWorkers`。
- **錯在哪**：
  - 我原本把這個測試定為「高負載時偶發、P3 延後」。M7 新增測試檔之後，在預設平行度下它變成每次都失敗，但我沒有重新評估。
  - 執行者交回後，我只檢查了「受保護路徑」有沒有被改，沒有逐檔看測試與建置設定的 diff。

## 規則（How to apply）
1. 執行者交回後，獨立驗證時除了 npm 腳本，**也要跑審查閘門實際用的檢查命令**（例如 `review/checks/*.mjs`），兩者都要通過。
2. 對 `package.json` 的 scripts、`vitest.config.*`、`wrangler*.toml`、測試輔助設定，逐檔看 diff，不能只看受保護路徑。發現沒申報的改動，就把它記為偏離，並追查它是在掩蓋什麼。
3. 已延後的「不穩定測試」只要在新的切片裡出現失敗，就要重新判定等級。從偶發變成確定性失敗時，升級並修正測試本身（例如改用可控制的時鐘），不靠降低平行度遮住。
