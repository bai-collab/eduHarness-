# 操作步驟零散，讓使用者自己拼湊

- 日期：2026-10-02
- 情境：某內部 AI 服務專案（LibreChat 本機部署）。服務由 Claude 背景啟動，2 小時上限到了被停；我先給使用者一條 Git Bash 指令（使用者在 PowerShell 執行失敗），再給「先開 start-mongo.cmd、再開 start-librechat.cmd」兩個檔案。
- 使用者更正：指出操作入口分散、要自己拼湊很麻煩，要求能整合就整合，不要讓人猜步驟。

## 事實
- 交付給使用者的操作拆成多個入口（兩個 .cmd、要記順序、要開兩個視窗）。
- 給的指令語法與使用者實際 shell 不符（Git Bash 的 `&&` 在 Windows PowerShell 5.1 無效）。
- 第一版合併 .cmd 內含 UTF-8 中文與 LF 換行，cmd.exe 解析壞掉（指令被切斷、產生空的怪檔名）。

## 規則（How to apply）
1. **一個入口**：交付給使用者的操作，預設合併成單一入口（一個可雙擊的檔案／一個指令），由它處理順序、等待就緒、已在執行就略過、結束時一併關閉。不要讓使用者記順序、開多個視窗、在多個資料夾之間找東西。
2. **說明與入口放在一起**：操作說明、設定範例、啟動檔放在同一個地方（同一個 repo／資料夾），不要散在 workspace、projects、repo 各處。
3. **指令對準使用者的 shell**：給使用者自己跑的指令，先確認是 PowerShell、cmd 還是 Git Bash；不確定就給可雙擊的檔案。
4. **Windows .cmd 只放 ASCII＋CRLF**：中文訊息與邏輯交給 Node 腳本，.cmd 只負責呼叫它。
5. **交付前自己用使用者的方式跑一次**（雙擊／同一個 shell），確認一步到位，再交付。
