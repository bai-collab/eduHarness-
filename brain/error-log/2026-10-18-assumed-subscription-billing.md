# 預設使用者以訂閱登入 Claude，實際是 API 金鑰

## 發生了什麼

規劃 Claude CLI 圖形介面原型時，我在比較表與計畫假設中，把「保留訂閱額度」「第三方工具使用訂閱的條款」當成考量，並假設 SDK 沿用本機登入。使用者更正：用的是 Claude API 金鑰，不是訂閱。

## 原因

沒有先問計費／身分方式，就把常見情境當成使用者的情境。

## How to apply

- 涉及 Claude（或其他模型）接入、成本、條款的規劃，先確認計費方式（訂閱登入或 API 金鑰），再寫比較與假設。
- 未確認前，把兩種情境分開列，不把其中一種寫成前提。
- 使用 API 金鑰時，計畫須寫明金鑰的存放位置（環境變數）、不寫入檔案／畫面，並以 True／False 檢查存在與否。
