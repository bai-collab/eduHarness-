# 唯讀白名單漏掉 git 的寫檔參數；審批正規式漏掉多行指令

- 日期：2026-10-11
- 事實：
  - 某代理宿主的治理橋接（policy 模組）把 `git diff`／`log`／`show` 一律判成唯讀。實測 `git diff --no-index --output=<file> a b` 會寫出檔案，紀錄卻是 `READ_ONLY`，沒有跳審批。被判唯讀的指令也會略過「提到受保護路徑」的檢查，subagent 同樣能執行。
  - 審批規則 `harness.rm`／`harness.mv-cp` 用 `(^|[;&|(]\s*)` 當開頭錨點，沒有多行旗標。`echo ok` 換行接 `rm a` 時，比對不到規則。
  - 兩者都是 AGY（gemini-3.1-pro-high）外審發現的；本機 8 項單元測試和 8 項實機驗收全部通過，都沒有抓到。
  - 收據：保存在原工作區（未隨附）。
- How to apply：
  1. 寫唯讀白名單時，不能只看指令名稱或子命令；要逐一列出該指令會寫檔或執行外部程式的參數並擋下，例如 git 的 `--output`、`-o`、`--ext-diff`、`--textconv`，sort 的 `-o`，find 的 `-exec`、`-fprint`。
  2. 用正規式比對 shell 指令的「指令開頭」時，分隔字元要包含換行（`\r\n`），或改用多行旗標；測試一定要放多行案例。
  3. 「實機驗收全過」只代表測到的路徑正確；繞過型漏洞要靠反例思考或不同家族外審，不能拿驗收結果宣稱安全。
  4. **後續（同日外審第 3、4 輪）**：逐條補參數的黑名單一直被繞過，依序出現 `git -C <值> push`（全域參數的值被當成子命令）、`uniq - <輸出>`、`-oFILE` 黏連寫法、用引號包住參數（`"--output=…"`、`find . "-delete"`）。根因是用空白切分＋正規式解析 shell 無法完備。往後寫 shell 唯讀判定時，**先規定安全字元集**（出現引號、反斜線、`$`、大括號、萬用字元就不算唯讀），再做參數檢查；而且不要讓「唯讀」判定略過其他硬擋。連續 2 輪被找到同一類繞過時，就停下來改原則，不要繼續補參數追逐 PASS。
