# 工作區磁碟上 mutation 測試還原後被延遲寫入覆蓋

- 日期：2026-10-05
- 情境：某教學網站專案 M2 由 Claude `security-executor` 在專案目錄做 mutation 檢查：先破壞關鍵控制、跑測試確認會轉紅，再把原始碼還原。

## 事實（subagent 回報＋主 session 驗證）
- M2a 那一輪：還原後，某驗證模組還殘留「授權條件被突變為恆真」的突變碼，後來才發現並修正。
- M2b 修正那一輪：用 `cp` 還原後，`cmp` 與 `diff -r` 當下都顯示「相同」；但之後 Python 先前寫入的突變版本才落地，某存取控制模組的擁有者條件被突變成過寬的條件，等於越權存取（IDOR）被打開。最後是全套測試有 3 個 IDOR 測試失敗才抓到。
- 主 session 獨立核對（等待 5 秒後 grep 突變特徵、確認正確條件存在、重跑 tsc 與 vitest 108/108），確認最終原始碼是乾淨的。

## 推論與未知
- 推論：Windows 上不同程序（Python、cp）寫入同一檔案，可能有延遲落地或寫入順序交錯的情況。
- 未知：根因沒有證實，可能與防毒、檔案快取或程序結束時才 flush 有關。不得當成已知機制。

## How to apply
1. 在工作區所在磁碟上做 mutation 檢查，優先改在另一個本機暫存複本進行；或在還原後**等待數秒**，用雜湊（`Get-FileHash`／`sha256`）與乾淨快照比對，不要只信當下的 `cmp`／`diff`。
2. 同一份檔案只用一種寫入方式，避免 Python 與 shell 交替寫入。
3. 主 session 驗收安全切片時，一律獨立 grep 突變特徵，並重跑全套測試；verifier 也要確認 `src/` 乾淨。
4. 子代理回報「已還原」不能直接當成證據。
