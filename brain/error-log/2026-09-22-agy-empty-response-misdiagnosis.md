# AGY 空回應被誤判為未登入

## 事件

第一次 AGY 唯讀呼叫回傳：

- `status=SUCCESS`
- `response` 為空字串
- `denied_actions` 包含 `action=command`

主 agent 卻把這個結果說成「AGY 未登入」，並要求使用者重新登入。這個說法沒有身分驗證錯誤碼、HTTP 401、`AUTH_EXPIRED` 或 `LoginRequired` 支持。

## 實際原因

目前證據只支持「AGY 沒有產生可用報告，且某個 `command` 動作被拒絕」。第二次明確限制只使用 `read_file` 後，AGY 成功產生審查報告；這支持第二次的讀檔與任務執行可用，但不能回溯證明第一次的登入狀態或第一輪空回應的唯一原因。

## 錯誤模式

把「結果為空」直接跳推成「登入失敗」，混淆了：

1. 工具執行狀態。
2. 工具策略權限。
3. 身分驗證狀態。
4. 任務內容是否真正完成。

## 修正要求

之後遇到工具空回應、拒絕或非預期狀態，先保存原始欄位，分成「事實／推論／未知」，再決定是否用已授權的替代方式重試。沒有直接的身分驗證證據，不得向使用者宣稱未登入或要求重新登入。
