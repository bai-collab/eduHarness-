# 審查獨立性通則被反覆誤編成固定拓樸

## 本次遇到的困難

使用者指出架構 Artifact §04 一句「安全敏感節點永不指派給 Codex，一律改派 security-executor」有誤；原意是審查交給主 session 指定的模型、與做事的 subagent 不同，用意在不要自己審自己。這是一條**通用的審查獨立性原則**，我卻連續三輪把它編窄、編死：

1. 第一次落字：把它當 **security 專屬**規則，寫成「審查交主 session 指定的不同模型」——方向對，但仍綁在 security、沒抓到是通則。
2. 使用者要求一併對齊協定 §5.1/§5.2，我寫成「**執行與審查必為不同 agent／模型**」「仍走**專屬 security 角色**」——把它硬成一種固定拓樸。
3. 我還在口頭答覆說「**審查不歸 Codex／Codex 只做粗工、Claude 才審查**」——直接講錯：協定 §5.1 本就寫 Independent Reviewer 可以是「非作者的 Claude 角色**或 Codex sol**」。

使用者指出已重複說明多次，並強調工作模式有協作也有單獨做。第三次才收斂到唯一不變式：**誰做的，不由自己審**；審查者主 session 指派、可 Claude 可 Codex sol；協作/單獨由主 session 選。

## 為何會反覆編窄（根因）

第一，**用最先出錯的那個例子（security）去代表整條原則**。錯誤句出現在 security 段，我就把修正也鎖在 security，沒退一步看出使用者講的是「作者≠審查者」的通則。窄例綁架了通則。

第二，**把原則過度具體化成一種拓樸**。「不自審」是一條不變式，我卻寫成「執行與審查必為不同 agent」的固定結構，等於預設只有「協作（多 agent）」一種工作模式，忽略「單獨做」也是合法模式。原則被我硬鑄成一種實作。

第三，**塞進一個沒被要求的僵化預設**（Claude=審、Codex=做）。我腦內把角色分工簡化成固定分派，於是講出「審查不歸 Codex」，跟工作區既有規則（Codex sol 可當 reviewer）直接矛盾，還沒去核對現成文本。

第四，**每次被糾正就再改一次字面、卻沒回到原則層**。前兩次都是在措辭上打補丁（換個說法、加個角色），沒問自己「這條規則的最小不變式到底是什麼」。補丁式修正讓錯誤換皮不換骨。

## 之後如何避免

被更正一條規則時，先問「這條的**最小不變式**是什麼」，再落字；不要用引發問題的那個窄例（此處 security）的措辭去代表整條原則。

把**原則**和**拓樸/工作模式**分開。原則（誰做的不由自己審）是不變式；用協作還是單獨做、派幾個 agent、誰當審查者，是主 session 依任務選的實作，不寫死在原則裡。

寫「X 不能做 Y」這種排除句前，先去核對現成文本有沒有反例（此處協定 §5.1 已明寫 Codex sol 可審），不要憑腦內簡化的角色分工下判斷。

連續被同一主題糾正兩次以上時，停止再打字面補丁，回到原則層重述一次讓使用者確認，而不是第三次又改措辭。

## 快速操作準則

1. 更正規則先抓**最小不變式**再落字；別用窄例措辭代表通則。
2. 原則 ≠ 拓樸：不變式是不變式，工作模式（協作/單獨、幾個 agent、誰審）由主 session 依任務選。
3. 審查唯一不變式：**誰做的不由自己審**；審查者主 session 指派、非作者、不同模型，**可 Claude 可 Codex sol**。
4. 寫排除句（X 永不 Y）前先核對現成文本反例，別憑簡化分工。
5. 同主題被糾正 ≥2 次 → 停止字面補丁，回原則層重述確認。
