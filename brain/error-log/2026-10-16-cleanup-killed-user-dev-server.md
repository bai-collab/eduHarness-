# 測試清理指令誤關使用者自己開的本機伺服器

- **日期**：2026-10-16
- **專案**：某教學網站專案（wrangler dev，port 8791）
- **發生了什麼**：
  - 代理每輪驗證後用「找出命令列含 `start-dev.bat` 的所有 cmd.exe 並 `taskkill /T`」來清理自己啟動的 dev server。
  - 使用者同時雙擊 `start-dev.bat` 在測試；清理指令把使用者的視窗與伺服器一起關掉，使用者回報網頁不見了。
- **事實**：事後 `netstat` 查無 8791 監聽；清理指令的比對條件無法區分「代理啟動」與「使用者啟動」的程序。
- **錯在哪**：用名稱／命令列樣式批次終止程序，而不是只終止自己啟動、記下 PID 的那一個。

## 規則（How to apply）

1. 代理啟動背景伺服器時，**當下記錄 PID**（例如 PowerShell `Start-Process -PassThru` 取得 `.Id`，寫到 `workspace/<主題>/` 的 pid 檔），清理時只 `taskkill /T /PID <該 PID>`。
2. 禁止用命令列樣式（`-like '*xxx*'`）或程序名稱批次終止；使用者可能同時在跑同一支腳本。
3. 啟動前若連接埠已被佔用，先判斷是不是使用者的程序；是就**不要關**，改用其他埠測試或詢問使用者。
4. 交付「請你自己啟動」的指示後，該輪之後的驗證要避開使用者的連接埠，或先詢問。
