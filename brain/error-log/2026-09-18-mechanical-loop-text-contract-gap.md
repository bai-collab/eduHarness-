# 文字契約存在，但沒有接通機械層執行迴圈

## 事件

本次已建立 Claude Opus 4.8 高強度唯讀驗收 Skill，也有 Claude CLI 包裝程式、執行狀態工具、證據記錄器與驗證器。先前容易把「這些檔案存在」說成「系統已有受管驗收迴圈」。實際讀碼後，這個說法不成立：模型可以提出文字，部分工具可以記錄事件，但還沒有一個受保護的控制器負責合法狀態轉移、實際派送、失敗回修、重新驗證與最後接受。

## 已確認的證據

（以下檔案皆位於原工作區 harness，未隨本工作區提供。）

1. `dispatch.mjs` 產生的是 `plan-only`，`executed` 固定為 `false`；它準備路由，沒有替任務執行操作。
2. `execute.mjs` 的 `externalExecutionRecord()` 可以讀取任務輸入的 `executed:true` 與 `run_id`，再把它放進執行產物。這是自填聲明，不是可信程序事件。
3. `verify.mjs` 主要驗證計畫與結構化證據；介面證據即使格式正確，也尚未自動綁定證據記錄器的信任錨與實際程序事件。
4. `run.json` 已有版本、鎖、事件、`intent`／`result`、重入對帳與恢復狀態；但 `resume.mjs` 只回報下一個動作，不會替控制器執行派送、驗證或回修。
5. `recorder.mjs` 已有雜湊鏈、信任錨與監督者，但目前沒有接到主 `dispatch → execute → verify` 路徑。
6. 記錄器在 `recorder.mjs` 對呼叫者提供的 `promptBytes` 做雜湊；啟動時卻只把 `argv`、`cwd`、`env` 傳給 `spawn.mjs`，而 `spawn.mjs` 使用 `PATH` 上的 `codex` 並忽略標準輸入。現況不能機械保證「被記錄的契約就是實際送出的內容」或「被記錄的執行檔就是實際啟動的檔案」。
7. 先前 Claude 真實審查確實完成並回傳 `FAIL`；這證明審查工具能回傳結論，不證明它已經是修正控制器，也不證明本機 `12/12` 測試代表真實模型可用。

## 根因

把四種不同事情合在一起看：

- **文字契約**：告訴模型應該怎麼做。
- **建議結果**：模型說它建議修改什麼。
- **執行紀錄**：程序實際做了什麼。
- **接受裁決**：控制器依可信證據決定是否完成。

目前前兩項有文件與 Skill，第三項有尚未接主流程的記錄器，第四項仍有部分路徑採信任務輸入。因此這是「機械零件各自存在但沒有接線」的問題，不是再補一段提示詞就能解決。

## gpt-6-astra medium 讀碼討論的收斂結論

`gpt-6-astra medium` 建議下一步定義為「受管執行迴圈」，不要繼續只擴充審查 Skill：

1. 模型只回傳結構化建議；不能執行工具、寫正式檔、改政策、寫完成旗標，也不能自行把建議說成已核准。
2. 控制器是唯一能依授權、版本、預算與事件修改執行狀態的元件。
3. 執行者只能在核准的隔離工作區修改候選產物；不能改控制器、政策、正式證據或驗證結果。
4. 獨立驗證者讀固定候選快照並重跑必要檢查；是否要求不同模型或不同工作階段，由該節點政策決定，不把協作拓樸寫死。
5. 記錄器只保存證據，不把「記錄完整」判成「工作成功」。
6. `recording_complete`、`operation_succeeded`、`required_checks_passed`、`accepted` 四個結果必須分開保存。

## How to apply

1. 先修實際啟動邊界：同一份啟動清單要同時產生實際參數、實際送出位元組、沙箱範圍與記錄內容；不能一份給執行、一份給記錄。
2. 所有狀態轉移都由程式檢查目前狀態、事件角色、契約雜湊、`run_id`、`attempt_id`、`op_id` 與 compare-and-swap 版本；模型文字不能直接改狀態。
3. 副作用前寫入 `intent`，副作用後寫入 `result`。中斷時先對帳，已落地只補結果，未知就停，不直接重做。
4. 修正失敗且仍在預算內才回到建議節點；驗證服務暫時失敗只重試驗證，不讓執行者盲目再改檔。
5. 相同錯誤指紋沒有新輸入或新證據時停止；建議初始修正預算為兩輪，總候選版本不超過三個，最終期限由控制器計算。
6. 證據鏈損壞、身分不符、信任錨不可用或無法判斷副作用是否落地時，採 fail-closed，回到人工決策，不以另一份自填報告補洞。

## 不得再宣稱

- `SKILL.md` 存在 ≠ 模型已收到並遵守契約。
- `execution.status: completed` ≠ 受審系統通過。
- 證據記錄器測試通過 ≠ 真實執行路徑已接通。
- `12/12` 本機測試通過 ≠ 真實模型、瀏覽器或教學成效通過。
- `run.json` 有狀態欄位 ≠ 狀態轉移已由機械閘控制。

本紀錄只描述已核對的缺口與設計方向；受管執行迴圈尚未在本次建立或實跑。
