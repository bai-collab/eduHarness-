# Workflow 契約與非權威範例

## 必要輸入

- 教材或來源
- 學習目標
- 學生年段
- 已核准的 `web` 闖關分支
- 需要空間理解的 Pilot 物件
- 教室場域、目標裝置與網路
- 可及性需求
- 評量方式
- 資產與授權限制
- Pilot 可用工時與停止條件

缺少教材時，唯一允許的內容輸出是教師 intake、缺件清單及空白契約。

## 3D 必要性判斷

先分類：這個 3D 是**遊戲美術**（地圖、寶箱、演出、粒子）還是**學習物件**？美術層與學習成效無關，只以動機、成本與可及性決定，不進下表；只有學習物件才用下表判斷 3D 是否不可替代。

| 問題 | 是 | 否 |
|---|---|---|
| 學生需要從不同角度觀察嗎？ | 繼續判斷 | 優先 DOM／SVG |
| 深度、遮蔽或內部構造會影響理解嗎？ | 繼續判斷 | 優先 2D |
| 平面圖、影片或分步插圖是否已足夠？ | 優先 2D | 可進 Pilot |
| 3D 任務能以可觀察指標比較學習效果嗎？ | 可進 Pilot | 停止 |

## 非權威 synthetic 示例

> 此例只測 Workflow 欄位是否完整，不是課程事實、教案建議或成效證據。

- 假想年段：國中
- 假想主題：三個相連齒輪的轉動方向
- 假想目標：學生能預測各齒輪轉動方向並說明相鄰齒輪的關係
- DOM-only：用箭頭按鈕逐步顯示齒輪方向，學生選擇第三個齒輪方向
- 3D Pilot：一組可旋轉觀察的三齒輪模型，3 個熱點分別選取齒輪
- 比較：答對率、完成時間、錯誤類型與教師觀察
- Kill Switch：`quest3d=off` 時只顯示 DOM-only

不得從此例推論 3D 一定比 2D 有效。

## 完成證據

- `intake-only`：缺件清單與未填欄位清楚。
- `spec-ready`：七份契約檔完整，且 3D 必要性判斷可追溯。
- `implementation-preview`：Task Packet、安裝預檢、檔案與依賴預覽完整。
- `pilot-evidence-ready`：具真實裝置量測、DOM／3D 比較、可及性結果及教師裁決。
