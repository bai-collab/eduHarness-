# 可玩世界備課（playable-world-prep）

把「把教材做成互動頁」的隨手嘗試，換成**可重現的備課紀律**：先判斷這主題該不該做成可玩世界、把 AI 產的知識庫**查核過**、再把實際生成**路由到既有生成 skill**，最後過三道查核關。

此 skill **不自己生成頁面**——它管的是「該不該做、做哪種、事實對不對、指不指向學習目標」。真正的生成交給下方路由的 skill。

規格全文：`projects/edu-playable-world-prep-sop/26-09-10-teacher-prep-sop.md`；示範知識庫：`projects/edu-playable-world-prep-sop/examples/`。

## 何時觸發

老師想把教材/主題變成「學生調一個東西、畫面會有意義回應」的可玩探究頁；或提到「把這課變可以玩／一本書變互動／做成模擬讓學生自己發現」。

## 反觸發（優先於觸發）

- 純記憶事實、單一正確答案、選擇題／連連看型 → 會退化成「點擊答題考卷」（正是要避免的反例）。
- 沒有互相影響變因的純事實教材。
- 使用者明說只要投影片或純文字。
- 一句判準：**「學生調一個東西，畫面會不會有意義地回應？」** 不會 → 做成好圖或好投影片就夠，別硬做。

## 四步 SOP（照做）

1. **plan-mode 建知識庫**：先請 AI 把教材整理成結構化知識庫（概念/關係/關鍵數字），**先不做網頁**。
2. **查錯（事實關）**：請 AI 回頭查自己哪裡寫錯/猜的；**數字、年代、因果一律以課本/官方為準**，AI 自述不採信；不確定者擱置或刪。
3. **做可玩頁（路由生成）**：依主題型態把生成交給對應 skill（見下），**一頁一機制**、變因要有意義回應。
4. **部署 + 課前自玩**：做成可離線/可分享頁；**課前自己先玩一遍**確認回應合理無誤導。

## 路由規則（本 skill 不自造，一律轉派）

| 主題型態 | 交給 |
|---|---|
| 多變因互相牽動的活系統 + 因果圖 | `causal-sandbox-inquiry` |
| 循序關卡、學習機制外殼 | `material-to-quest-game` |
| 完整 Web 遊戲編排（資產→實作→驗證） | `educational-web-game-workflow` |
| 先講清楚機制再決定要不要做 | `explain-visual` |
| 數學臆測單元的五階段素材 | `conjecturing-five-stage` |

## 三道查核關（交付前必過）

| 關 | 問 | 不過就 |
|---|---|---|
| 事實 | 數字/因果對過課本或官方？ | 刪或標「待查」，不上場 |
| 回應 | 調變因，畫面回應是否有意義且正確？ | 調參數或縮範圍 |
| 教學 | 互動有沒有指向學習目標？ | 換互動或改回投影片 |

## 一節課範圍界定

一頁一機制、一個要學生「發現」的關係；留時間給學生戳→發現→講出來；做不出或查核不過**要能退回投影片**。

## 邊界

- 不處理真實學生個資（用公開教材或去識別範例）。
- 對外發布頁面屬副作用 → 交老師自行決定/發布，不自動公開。
- AI 產的知識庫必是未查核輸入，事實關為硬關。
