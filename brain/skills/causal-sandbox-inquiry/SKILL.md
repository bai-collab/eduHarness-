# 因子模擬探究沙盒（Causal Sandbox Inquiry）

## 定位

把「有多個互相牽動變因」的教材，轉成一個**會回應學生的活系統**：學生調整條件、即時看到系統反應、在反覆實驗中**親手發現一張因果拓樸圖**，最後把假設帶到真實世界做長期手作驗證。

這個 skill 產出的是**遊戲／模擬的設計與可玩原型規格**，不等於完成正式課程、真實課堂成效或部署。學習狀態與無障礙操作永遠由 DOM 承擔；模擬視覺是可關閉的一層。

## 核心主張（為什麼這個方法有效）

好的探究模擬 = **能動性 + 活的回饋 + 可發現的因果結構**。三件事缺一就會退化成「互動式考卷」：

1. **能動性**：學生的操作真的改變世界，不是點開一個固定答案。
2. **活的回饋**：畫面上有會即時反應的「活物件」（生物、價格、粒子、族群），光是戳它就有玩具感；回饋是**看得見的系統狀態**，不是一排冷冰冰的儀表數字。
3. **可發現的因果結構**：變因**互相牽動**——有疊加、有跨域副作用、有甜蜜點、有時間延遲——學生透過實驗把這張因果網一條一條**發現**出來，而不是被告知。

> 關鍵測試：如果把玩家的操作拿掉，世界還會不會「活著、有變化」？如果不會，你做的是考卷不是沙盒。

## 觸發與反觸發

- **觸發**：把教材做成互動模擬／變因模擬／系統思考遊戲；主題有多個互相影響的條件（生態、供需、力學、化學平衡、傳染病、水資源、都市、營養…）；使用者想「調條件看結果」「疊加會怎樣」「畫因果圖」；或已發現點擊＋答題很無聊，想要「會回應的活系統」。
- **反觸發**：純知識問答、背誦、單一變因的靜態圖表、本質是選擇題／連連看的互動考卷；沒有互相影響變因的純事實教材。若使用者其實只要一般闖關外殼，導去 `material-to-quest-game`；只要完整 Web 專案編排，導去 `educational-web-game-workflow`。

## 必要輸入（缺就先問，不要瞎猜）

教材／學習目標、學段與年齡、**候選變因（可操作的條件）**、目標裝置與網路、可及性需求、時間、評量方式、資產限制。缺少會改變教學設計的資料時，只輸出缺件報告與候選變因草案，請使用者確認。

## 執行流程

### Gate 0 — 判斷這個主題適不適合

問一句：**這些變因會互相牽動嗎？把某個東西轉一圈／推到極端，會不會冒出平面講解看不到的連鎖？** 若變因彼此獨立、或只有單一因果，本方法沒有優勢，直說並建議別的形式。適合才往下。

### 1. 因子萃取

從教材找出 **3–7 個可操作的變因**，每個標明：玩家怎麼操作（盡量是**直接手勢**：點、拖、擠、灑，不是抽象滑桿）、快變數還是慢變數、對應的學習概念。變因太多會壓垮玩家，尤其手機——寧可少而互相牽動，不要多而各自獨立。

### 2. 交互拓樸設計（本 skill 的靈魂）

只做「單一效應」會變成一排獨立開關，很快就膩。真正的探究來自**變因互相牽動**。刻意設計以下幾類交互，讓學生自己發現：

- **疊加**：兩個因子一起才有效（例：關燈＋樹液 才吸引得到獨角仙）。
- **跨域副作用**：解一個問題卻製造另一個（例：加濕度幫了樹液，卻積水招來蚊蟲）——這種「牽一髮動全身」最能引發系統思考，也常能把不同課程單元串成同一個系統。
- **甜蜜點／過量反噬**：好因子過量會壞事（例：落葉腐植質好，但太濕會發霉）。
- **時間延遲**：慢變數＋時間才看得到結果（例：維持棲地幾晚才長出幼蟲；一直被捕捉則永遠養不起來）。

把這些整理成一張**交互拓樸表**：節點是變因與結果，邊是效應（促進／抑制／副作用），標明疊加條件與延遲。這張表就是模擬的骨架，也是學生最後要發現的因果圖。

### 3. 活系統回饋（玩具感優先）

用**會動、有個性的活物件**呈現系統狀態（agent：生物、車流、價格泡泡、族群），讓操作在**幾秒內**看到可見反應。先確保「光是戳這個系統就好玩」（toy-first），再談目標與關卡。回饋以畫面為主、數字為輔。

### 4. 發現式因果圖（把探究變成看得見的東西）

維護一本**觀察日誌**：每當學生的操作**觸發一個因果**，就在圖上**新增一個節點／一條邊**（促進綠、抑制／副作用紅），並記一句白話。玩到後面，畫面上長出一張**他自己發現的因果拓樸圖**——這是本方法的招牌產物，把「觀察→假設」外化成可回顧的結構。

### 5. 兩段式關卡

- **自由段（探索，不會輸）**：無限嘗試、不計分，變因**漸進登場**（不要一次丟 7 個），觀察日誌自動記錄發現。目的是玩出因果。
- **挑戰段（驗收，有星等）**：給限制＋突發＋目標（例：3 個週期內把族群穩定在某值），逼學生用學到的因果應變。挑戰來自**系統的難度**，不是選擇題。

### 6. 模擬 → 真實手作的橋接

模擬是**假設引擎**，不是終點。沙盒形成假設後，發**現場任務卡**（去真實場域記錄對應變因），再給一段 **2–4 週的改善追蹤**（實際動手改變條件、每週觀察回填）。沙盒引發假設，真實世界驗證與修正——這時它是 web＋實體的混合探究，也才完成「發現問題→解決→調整」的完整循環。

### 7. 探究對應與評量

明確對到探究循環：觀察→假設→實驗→驗證→調整。自然帶出幾個科學態度：**系統有副作用（解一個問題可能製造另一個）**、**沒觀察到 ≠ 不存在**、**結論是目前最合理的推測、要改善再驗證**。評量看的是學生發現的因果圖品質與應變推理，不是背標準答案；不寫入 localStorage／資料庫，評量以畫面歷程呈現。

## 技術與架構契約

- **DOM baseline 先行**：控制、狀態、目標、因果日誌都在 DOM，鍵盤可操作、螢幕閱讀器可讀；WebGL／Canvas 關閉或低效能時，用文字版仍能完成同一學習任務。模擬只是可關閉的「島」。
- **模擬島**：多個會動的 agent 用 **Canvas 2D** 手刻輕量迴圈即可，通常**不需要遊戲引擎**；除非內容本身是立體且 2D 會遺失深度，才考慮 3D（此時導去 `quest-threejs-adoption`）。
- **手機優先**：直接手勢、大點擊目標、保守效能預算；量測冷啟動、frame-time、連續操作與降級。
- **自足靜態**：純前端、不呼叫 runtime AI、不連資料庫、不寫瀏覽器儲存、不載入未知遠端資源；資產自製或已驗證授權。
- **無障礙與安全**：`prefers-reduced-motion` 停自動過場與非必要動畫；避免三閃與動暈；context loss 不破壞學習狀態；不收集學生個資。

## 反例與品質準則（用兩次失敗換來的）

這些是本方法最容易做壞的地方，務必自檢：

- **不要做成「點擊＋答題」的互動考卷。** 「轉一轉再點」「連連看再判對錯」都還是考卷穿新衣。挑戰必須來自**會反抗／回應的系統**，不是來自選對答案。
- **變因不要各自獨立。** 一排互不影響的開關／滑桿很快就膩；價值在**互相牽動的那張網**。
- **回饋要活、要看得見。** 只有數字跳動＝儀表板，不是玩具；要有會動的 agent。
- **先做「核心玩具」原型驗證好玩，再疊因子。** 一次把所有變因做完風險很高，容易做出「複雜但無聊」。先用最小系統（1–2 個會即時反應的因子＋活 agent）證明戳起來有意思，好玩再往上長。
- **誠實面對「無聊」回饋。** 如果使用者說無聊，通常是**核心互動模型**錯了（不是美術、不是難度）；換模型，不要換皮。
- **美術別過度承諾。** 手繪／水彩風配上粗糙 3D 反而更糟；程序化就走 toon／flat＋手繪貼圖，把心力放在 agent 的動作與氛圍。

## 輸出契約

依情境產出（缺輸入時只出缺件報告＋草案，不宣稱完成）：

1. **因子清單**：變因、操作手勢、快／慢、對應概念。
2. **交互拓樸表**：節點、邊（促進／抑制／副作用）、疊加條件、延遲——含至少一個跨域副作用與一個甜蜜點／過量反噬。
3. **活系統與 agent 行為規格**：agent 狀態機、對各因子的即時反應規則。
4. **發現式因果圖規格**：哪些操作觸發哪些邊被「發現」、白話說明。
5. **兩段式關卡**：自由段的因子登場順序；挑戰段的限制、突發、目標、星等。
6. **sim→real 橋接**：現場任務卡＋長期追蹤紀錄流程。
7. **技術與可及性契約**：DOM baseline 對照、效能預算、fallback。
8.（可選）**可玩原型**：自足單檔（Canvas＋DOM），先做核心玩具再擴充；未取得安裝／部署授權前不安裝套件、不部署。

## 與其他 skill 的關係

- 只要一般闖關外殼（關卡／題庫／回饋）→ `material-to-quest-game`。
- 要從教材到 Web 實作到驗證的完整編排 → `educational-web-game-workflow`。
- 內容本身立體、2D 會遺失深度 → `quest-threejs-adoption`（否則預設留 2D／Canvas）。
- 題目還很模糊、要先發散收斂決定方向 → `creative-collaboration-loop`。
