# 臆測五階段

## 定位

把**已提供的數學單元教材**改寫成林碧珍臆測教學模式的教案：學生自己造例、自己提出猜想、用反例效化、加限制條件一般化、最後以先備知識證實。**課本直接給定義的地方，改成學生產出後才命名。**

參考實作：`參考文件/博論/教案-第七單元-臆測五階段-全單元/`（五上第七單元擴約分與加減，7 節，經七輪獨立驗證）。

## 觸發與反觸發

- 觸發：`臆測五階段`、臆測教學、臆測任務、把某單元改成臆測、conjecturing teaching。
- 不觸發：一般教案撰寫（改用 `lesson-plan-authoring`）、既有教案分層（`lesson-differentiation`）、命題（`item-authoring`）、教材轉遊戲。
- 缺教材、年級、節數或單元範圍時，只輸出缺件清單，不自行假設。

## 必要輸入

單元教材（課本／教師手冊原始檔）、年級與科目、單元教學目標、課本建議節數、班級人數與組數、可用教具、學生先備狀況。

## 五階段規格

| 階段 | 活動形式 | 學習內容 | 產出 |
|---|---|---|---|
| 造例 | 個人 → 小組 | 建立 → 檢驗 → 分類 → 彙整資料 | 小組工作單 |
| 提出猜想 | 個人 → 小組 | 提出 → 分享 → 檢驗 → 支持／反駁 → 歸類 → 彙整 | **每組 1 條**小組猜想 |
| 效化 | **全班** | 分享 → 檢驗 → 效化 → 歸類 → 彙整 | 全班猜想 |
| 一般化 | 全班 | 推廣 → 加全稱量詞與限制條件 → 精緻化 | 數學命題 |
| 證實 | 全班 | 列舉法／操作證明 → 演繹推理 | 被說服的恆真命題 |

**術語固定為「造例／提出猜想／效化／一般化／證實」。** 文獻中五階段模式的出處年份有 2015／2016／2019／2021 四種歸屬並存，未解；引用時須查證，不得逕採單一年份。

## 硬性設計約束

1. **教材事實必須回原始檔視覺核對。** 文件轉檔會讓分數的分子插進分母數字中間（如 `1 2 8 4` ＝ 18/24），且箭頭、圖示全滅。所有數值、表徵樣式、圖示規格、活動編號一律以原檔為準，並建立 ledger 逐筆標註核對狀態。
2. **造例材料必須異質分配。** 全班拿到同質起始素材時，猜想池會單薄、效化階段必然空轉。至少要讓「可雙向操作」與「只能單向」的素材同時出現。
3. **猜想池必須同時含恆真、非恆真、錯誤三類。** 課本通常只提供恆真猜想；沒有可打的靶，效化與一般化會空轉。列為必要條件檢核。
4. **定義延後到一般化階段才命名。** 學生產出性質之後才給名稱，名稱是學生發現的標籤而非先給的定義。分類欄名不得使用目標術語。
5. **每組只交 1 條小組猜想。** 收斂是提出猜想階段的職責，不得外溢到效化階段。
6. **不使用連等式**（若課本明文禁止）；**倍數變化以箭頭標在分子上方與分母下方**（若課本明文規定）。
7. **引用課本發現疑似錯誤不得代為修正**，照引並加註疑義。
8. **成功條件分個人層級與全班層級兩層**，全班層級明標「衡量教學設計，非學生成績」。
9. **無文獻依據的數值一律標「設計者目標值」**；不得出現「已實施」「已驗證有效」。

## 差異化的兩條判準

- **判準 A（操作層）**：措施觸及該階段核心決策的**比例**。0 項 🟢／部分 🟡／**全部** 🔴。用比例而非絕對數，否則在決策數最少的任務上會失效。
- **判準 B（概念層）**：是否說出目標猜想的**關係內容** → 一律 🔴，**不論用術語、白話或疑問句**。看的是話語指出了什麼，不是怎麼說。

判準以**措施的完整內容含教師話語**為判定對象；措施名稱無法判定等級。🟡 措施須附四項約束：單次使用、學習單標記、研究計分排除、全班比例上限。

## 執行流程

1. **語料與術語**：確認五階段術語，並記錄出處爭議。已完成者沿用 `參考文件/博論/決策-臆測五階段術語定案與語料清單.md`、`收斂-臆測五階段教學流程與階段教學目標.md`，不重跑。
2. **教材事實 ledger**：抽出目標、節數、活動、教學提醒、迷思清單、習作對應；數值類回原檔視覺核對（PDF 可用 `uvx --from pypdfium2 --with pillow pypdfium2 render` 隔離渲染為圖再讀）。
3. **逐小節設計臆測任務**：核心猜想、異質造例材料、猜想池（含反例靶）、反例題組（每道須數學驗算）、一般化的限制條件與全稱量詞、證實的先備知識清單、逐事件時間帳。
4. **全單元總表**：節數配置、目標涵蓋檢核、任務間依賴、課本活動處置對照、編號索引。
5. **學習單、評量規準、差異化**：學生版不得出現待命名的目標術語；評量分「教學用成功條件」與「研究用編碼」兩層並禁止研究編碼用於成績。
6. **獨立驗證**：交 fresh-context `verifier`，只回 CONFIRMED／REFUTED。

## 驗證契約

- 檢核項：目標涵蓋、時間帳逐層加總、**反例逐道數學驗算**、教材事實回 ledger／原檔、編號跨檔無衝突、術語一致、紅線逐條、跨檔矛盾掃描。
- **判 REFUTED 後修正，必須再驗。** 參考實作中 58 項缺失有 29 項（50%）是修正過程自己製造的，三種型態：**只加不改**（加了正確的一行沒刪錯的那行）、**局部修未掃全域**（改了一個檔沒掃其他檔）、**修正引入未宣告的規則**。
- 修正時固定自問：舊的那句刪了嗎？其他檔有同一句嗎？

## 輸出契約

`ledger-教材事實.md`、各小節任務檔、`全單元總表.md`、`學習單內容稿.md`、`評量規準.md`、`差異化方案.md`、`未取得清單-待補.md`、`審查紀錄.md`。

## 停止規則

- 缺教材、年級、節數、班級組數時，只輸出缺件清單。
- **時間帳塞不進配置節數時，停下來回報實際分鐘數請使用者裁決，不得灌水說塞得下。**
- 原檔視覺核對仍看不清數值時，標待補、**不猜**，請使用者提供清楚影像。
- 猜想池湊不出非恆真或錯誤猜想時，回頭改造例設計，不得跳過效化階段。
- 教具附件、班級人數、是否有特殊需求學生未知時，標為阻塞定稿項，不得宣告完成。
- 涉及學生個資、錄影錄音、IRB 或正式送件時，先要求使用者核准。
