# 讓 AI 讀 Word／PDF

你不需要自己動手轉檔——把檔案拖進對話,AI 會自動判斷要不要先轉成 Markdown 再讀。這篇要說的是「它為什麼有時候會轉、有時候不轉」,以及「為什麼問版面問題時它會叫你去看原檔」。

## 先分類:你要的是內容,還是版面

這是整件事的核心規則,分兩個方向:

| 你要的是 | 該怎麼處理 | 為什麼 |
|---|---|---|
| 摘要、搜尋、抽取重點、比較內容、翻譯、審查意義或論點 | 一定先轉成 Markdown 再讀 | 內容類任務只需要文字,轉成 Markdown 讓 AI 讀起來更準確 |
| 字型、邊界、頁碼、行距、章節分頁、視覺表格／圖、算繪結果、官方版面符合性 | **絕對不能轉**,必須直接檢查原始檔 | 轉換過程會丟掉版面資訊,轉出來的 Markdown 只剩文字,不能拿來當版面正確與否的證據 |
| 兩種需求混在一起 | 版面那一邊優先,那個檔案不會被轉換 | 一旦牽涉版面,原始檔案是唯一可信的證據來源 |
| 檔案本來就是 Markdown 或原始碼 | 直接讀,不用轉 | 已經是純文字格式,沒有轉換的必要 |

支援轉換的檔案類型:DOCX、PDF、PPTX、XLSX、XLS、MSG、HTML、CSV、JSON、XML、EPUB、IPYNB。

## 實際上你要做的事

把檔案直接拖進 Claude Code 的對話,或告訴它檔案在哪裡。剩下的判斷——要不要轉、轉哪一個——AI 會自動處理,你不需要下任何轉檔指令。

如果你問的是版面相關的問題(例如「這份 PDF 頁碼對不對」「這個 DOCX 的邊界符合規定嗎」),它會告訴你需要看原始檔案,而不是直接拿轉換後的文字回答你——這不是它偷懶,是因為轉換後的 Markdown 本來就沒有版面資訊可以拿來當證據。

## 你會拿到什麼

**要內容**的情況下,你會拿到一份 `.md` 檔案,保留原始文件的文字內容,供 AI 讀取、摘要、搜尋或抽取使用。

**要版面**的情況下,你不會拿到任何轉換檔——AI 會直接檢查你提供的原始檔案本身。

## 常見狀況

**「我問它 PDF 的頁碼對不對,它說要看原檔」**
對,頁碼、邊界這類版面問題,轉成 Markdown 之後這些資訊就不存在了,只有原始 PDF 才看得出來,所以它會請你直接看原檔,或把原檔交給它檢查。

**「Excel 轉出來表格跑掉了」**
表格結構複雜(合併儲存格、多層標題、跨表公式)時,轉成 Markdown 可能無法完整保留原本的排列。這種情況下,涉及表格版面正確性的問題,要回頭看原始 XLSX 檔案,不要用轉換後的文字當依據。

**「我以為它會幫我轉檔存起來」**
它轉出的 Markdown 是為了讀取內容用的中間產物,不是刻意要給你的交付檔案。如果你要的是排版正確的成品,那要直接處理原始檔案,不是拿轉換後的 Markdown 去排版。
