# NOOA 能力矩陣（分享版）

本頁說明 eduHarness 上層 harness 吸收自 NVIDIA「六項 agent harness 能力」（NOOA）的能力現況。每一條能力都由確定性外層程序強制、並有測試背書；本頁為上游 SSOT 於 2026-08-10 產出的定版快照。

> 狀態：`native`＝原生實作；`partial`＝核心已實作、後續切片進行中。

| 能力 | NOOA | 狀態 | 對教師的保證 | 失敗即擋（fail-closed 訊號） |
|---|---|---|---|---|
| 型別化輸入輸出契約 | NOOA-1 | native | 技能缺必要輸入時，執行前就明確阻擋並指名缺項，不會默默產出錯的成品 | `BLOCKED_BEFORE_RUN` |
| 資源引用與有界預覽 | NOOA-2 | native | 大教材以引用＋有界預覽處理，不反覆整份載入；引用經雜湊驗證，內容被竄改即拒用 | `full_resource_not_injected`／`integrity mismatch` |
| 可程式化流程迴圈 | NOOA-3 | native | 技能流程是顯式狀態機，跨平台一致；格式錯誤或無界迴圈在執行前被擋下 | `WORKFLOW_STAGE_INVALID` |
| 顯式任務狀態 | NOOA-4 | native | 任務中斷後可從持久狀態還原進度與重試次數，不靠對話記憶；人工核准狀態不可被模型竄改 | 非法狀態拒絕寫入 |
| 受治理的模型可呼叫記憶 API | NOOA-5 | partial | 學生個資與機密即使被要求寫入、即使證據齊全，也一律阻擋進入知識庫（核心＝寫入 gate） | `MEMORY_WRITE_BLOCKED` |
| 宿主能力清單 | NOOA-6 | native | 技能宣告所需的執行能力；環境缺該能力時明確回報「無法執行」，而非私自改用別的方法 | `CAPABILITY_UNAVAILABLE` |

## 這代表什麼

eduHarness 對教師的核心承諾，是把「靠模型自己遵守文字規則」升級為「由確定性程序強制」——尤其在**輸入完整性、學生個資保護、人工核准不可竄改、跨平台可重現**這四件事上。每一條能力都對應一個「失敗就擋」的訊號，而不是事後提醒。

型別化契約（NOOA-1）已隨技能一起提供，缺輸入會在執行前給你明確提示。其餘能力的引擎留在上游治理層，本分享版以本頁與相關說明文件呈現其保證。
