# 記憶層與 context 預算

`brain/` 底下有好幾個資料夾——instincts、knowledge-base、errorLog、experience。第一次看會以為重點是「分門別類」，其實不是。

**重點是：什麼時候被讀取。**

## 兩種讀取時機

AI 每次對話能處理的資訊量有上限（這個上限叫 context）。記憶層分成兩種：

- **啟動載入**：每次對話一開始就讀，不管你這次要做什麼。
- **觸發載入**：只有相關任務發生時才讀。

這個分界才是整個設計的核心。

## 為什麼分界這麼重要

啟動載入是**固定成本**。不管你這次問的是出題還是備課，那些字都會先佔掉一部分 context。塞進啟動層的東西越多，AI 真正拿來思考你問題的空間就越少。

而且這種損耗是**無聲的**——不會報錯，你只會覺得 AI 今天怎麼有點笨、抓不到重點。等你發現，通常已經被拖累一陣子了。

所以設計原則很簡單：**啟動層只放幾乎每次都用得到的東西，其餘一律等觸發**。

## instincts 為什麼有 200 行硬上限

`brain/instincts/` 是唯一「整個目錄無條件全量載入」的層——每次啟動，裡面每一行都會被讀進去。

正因為它是無條件的固定成本，它必須有上限。沒有上限，它會隨著時間一條一條長大，慢慢吃掉每一場對話的空間，而且是前面說的那種無聲吃法。

所以規則是：**全目錄合計不得超過 200 行**，超過就必須合併或淘汰，不能無限增長。一條規則要進 instincts，等於是在說「這值得每一次對話都付一次錢」——門檻應該很高。

## errorLog 與 experience：修的東西不一樣

這兩層都是「任務後回寫」，但修的東西不同：

- **errorLog** 記「什麼壞了、根因是什麼」——修的是**行為**。下次遇到同樣狀況，別再那樣做。
- **experience** 記「我當初怎麼判斷的、那個判斷哪裡不對」——修的是**判斷方式**。

同一件事可能兩層都要寫：錯誤本身進 errorLog，「為什麼當初會做出那個判斷」進 experience。

## 為什麼「已驗證」是進入門檻

errorLog 和 knowledge-base 都要求內容**已驗證**才能寫進來。這條看似囉嗦，其實是保命的：

一條**猜測的**根因比沒有記錄更糟。沒記錄，下次至少會重新查；記了一條錯的，下次會照著錯誤的結論去避一條根本不存在的錯路，白繞一圈還以為自己在遵循經驗。

## 為什麼不乾脆全部都啟動載入

「全部都先讀進來不是最保險嗎？」——這正是這套設計要避免的。全部載入意味著每次對話都付最高的固定成本，換來的是絕大多數用不到的資訊。觸發載入是拿「偶爾多花一步去讀」換「每次都省下大量空間」，這筆帳幾乎總是划算的。
