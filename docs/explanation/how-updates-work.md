# 更新怎麼運作、你的修改會怎樣

這個 repo 有一個和多數專案不同的性質，先講清楚，之後你對更新的所有疑問都能自己回答。

## 這裡是產出物，不是原始檔

你 clone 到的 eduHarness，是從一個內部工作區**自動產生**的發佈版本，不是有人在這裡手工維護的原始檔。

原始檔在上游。這裡的技能、腳本、文件，都是上游定期「轉出來」的一份快照。

這個性質帶出三件事，逐一說。

## 一、你新增的檔案，更新不會刪

執行 `git pull` 取得新版時，**你自己新增的檔案不會被動到**。

比如你在 `brain/errorLog/` 寫了自己的踩坑筆記、在 `brain/knowledge-base/` 存了自己的參考資料——這些檔案不在版本控制裡，`git pull` 不會碰未追蹤的檔案。它們會留下來。

## 二、你改過的內建檔，更新會覆蓋

反過來，如果你改的是**內建檔**——技能的 `SKILL.md`、各層的 `README.md`、`TEMPLATE.md`、或 README——那麻煩了：

- 下一次發佈時，上游的新版本會覆蓋你的修改。
- `git pull` 時可能直接跳出衝突。

因為這些檔案上游也在維護，兩邊都改同一個檔就會撞。

**想保留自己的版本**：不要改內建檔，另外開一個新檔（新檔屬於第一種，不會被覆蓋）。

## 三、想讓你的改動進正式版，走 issue

如果你覺得某個技能該改、某段說明有錯，直接在本地改是留不住的（第二點）。正確的路徑是：

1. 在 GitHub 開一則 issue 說明問題或建議。
2. 上游在原始檔修正、驗證。
3. 重新發佈，你 `git pull` 就拿到。

送 Pull Request 沒有用——下次發佈一樣會被覆蓋。所以本專案**不收 PR，只收 issue**。詳見 [CONTRIBUTING.md](../../CONTRIBUTING.md)。

## 一個常被誤會的點

有人以為「既然更新會覆蓋，那我寫在記憶層的東西也會被清掉」。**不會**——那是把上面第一點和第二點搞混了。

`git pull` 只覆蓋**被追蹤的內建檔**，只刪除上游明確刪掉的檔案。你自己新增的記憶檔是未追蹤的，它動不到。會被覆蓋的只有你去改的那些內建檔。

## 版本怎麼讀

版本採 CalVer：`v2026.07.4` 代表「2026 年 7 月的第 5 次發佈」（序號從 0 起算）。每版變更見 [CHANGELOG.md](../../CHANGELOG.md) 與 `RELEASE-NOTES/`。

## 為什麼是「自動產生」而不是「直接開放這個 repo 給大家改」

自動產生保證了每一份發佈都經過上游的同一套檢查（防重、掃描、驗證）才出得來，品質可預期。代價是你在這裡的直接修改留不住——但這正是換來「不會有人不小心把壞東西提交進公開版」的保證。想深度客製的人 fork，想貢獻的人開 issue，兩條路都通。
